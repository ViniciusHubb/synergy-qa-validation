# Requisitos Funcionais

## Introdução

Este documento consolida os requisitos funcionais do MVP Synergy a partir do
roadmap fornecido. O escopo não inclui itens de backlog nem funcionalidades
explicitamente fora do MVP.

## Requisitos

| ID | Requisito | Prioridade | Critérios relacionados |
|---|---|---|---|
| RF001 | O sistema deve permitir o cadastro de usuários Startup, Investidor Anjo e Profissional, com segmentação de perfil e nicho quando aplicável. | Alta | CA001, CA002 |
| RF002 | O sistema deve autenticar usuários por e-mail e senha e impedir o acesso com credenciais inválidas. | Alta | CA003 |
| RF003 | O Administrador deve poder disponibilizar eventos internos e externos com dados obrigatórios, capacidade e, quando aplicável, link externo. | Alta | CA004 |
| RF004 | O Investidor Anjo deve poder confirmar publicamente sua presença em um evento. | Alta | CA005 |
| RF005 | O sistema deve aplicar a prioridade de inscrição Premium e respeitar a capacidade máxima do evento. | Alta | CA006 |
| RF006 | A Startup deve poder publicar, editar, ativar, desativar e excluir vagas. | Alta | CA007, CA008 |
| RF007 | O sistema deve impedir que perfis não autorizados gerenciem vagas de uma Startup. | Alta | CA009 |
| RF008 | O sistema deve restringir comunidade, roadmap e templates de landing page a contas Premium. | Alta | CA010, CA011, CA012 |
| RF009 | Usuários Premium devem poder publicar e responder no fórum da comunidade conforme as permissões do MVP. | Média | CA011 |
| RF010 | A Startup Premium deve poder consultar e atualizar seu progresso no roadmap burocrático. | Média | CA012 |

## Fora do escopo desta rodada

Pagamento real do Premium, candidatura a vagas, diretório público filtrável,
recuperação de senha, confirmação de e-mail, painel administrativo completo,
notificações, busca/paginação e automação E2E serão tratados como backlog.
